## 1. 背景与目标

**背景**：产品设计蓝图已定稿（八大模块 + 老师风格 + 记忆贯穿）。技术选型定为方案 B（Next.js 全栈 + 在线 DeepSeek API + SQLite）。

**目标**：本计划聚焦「初期」——把产品最核心的链路跑通，让用户能本地启动、和 AI 对话、体验「术语标注 + 派生会话」这一核心差异化交互。

**完成标准**：`npm run dev` 可启动，能流式对话，术语能高亮并悬停查看，能派生子会话且会话树正确，数据落库、刷新不丢。

---

## 2. 方案概述

**选定方案**：Next.js 15 (App Router) + React 19 + TypeScript + Tailwind + shadcn/ui，接 DeepSeek 在线 API，SQLite（better-sqlite3 + Drizzle ORM）本地持久化。

**关键决策**：

| 决策点 | 选定 | 落选方案及原因 |
|--------|------|---------------|
| LLM 接入 | DeepSeek `v4-flash`(默认) + `v4-pro`(重任务) | 本地 Ollama：受硬件限制、离线质量低 |
| 术语标注 | 两段式（正文流式 + 术语结构化） | 流式 JSON：流式下偏移对应难、易错 |
| 数据库 | SQLite + better-sqlite3 + Drizzle | PGLite：生态较新、本地场景 SQLite 更稳 |
| 向量检索 | 初期 FTS5 全文检索，后置 sqlite-vec | 直接上向量：术语速查靠词典匹配足够 |
| 代码实践 | WASM 沙盒，本计划后置 | 本机环境：需先装依赖，违背初学者零门槛 |

## 6. 风险与对策

| 风险 | 影响 | 对策 |
|------|------|------|
| API key 已明文暴露于对话 | 泄露、被滥用 | 用户去 DeepSeek 后台轮换；key 仅存 `.env`（已 gitignore） |
| DeepSeek JSON 输出不稳定 | 术语结构化失败 | `@ai-sdk/deepseek` 自带 JSON 指令注入；加 zod 校验失败重试 |
| better-sqlite3 与 Next.js 打包 | 构建报错 | 配置 `serverExternalPackages: ['better-sqlite3']`，仅服务端引用 |
| 流式术语偏移错位 | 高亮位置错 | 用 `[[ ]]` 内联标记规避偏移问题（两段式） |
| 术语重复/误标 | 高亮噪音 | 本地种子词典过滤 + 常见词白名单 |
