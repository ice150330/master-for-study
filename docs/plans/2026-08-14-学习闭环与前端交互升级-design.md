# Mentor 学习闭环与前端交互升级实施计划

> 日期：2026-08-14  
> 状态：已完成（2026-08-15，阶段 0–18 均已独立实现、截图、验证和提交）
> 范围：前端体验、跨模块学习闭环、必要的数据与 API 基础、自动截图与视觉验收  
> 原则：每个阶段独立实现、独立截图、独立验证；上一阶段未通过视觉与功能门禁，不进入下一阶段。

## 1. 背景与目标

当前项目已经具备聊天、笔记、资源、实践、面试、复习、分析、白板八个可运行模块，但仍以独立的第一版垂直切片为主。下一阶段不能只补数据模型，也不能只做表面换肤，需要同时解决三类问题：

1. **学习闭环不连续**：术语、会话、笔记、练习、面试和复习之间缺少统一对象与跳转关系。
2. **复杂交互不可靠**：分支不继承上下文，流式请求存在竞态，历史术语解释丢失，各模块错误状态不一致。
3. **界面密度与层级不足**：模块已有统一色彩，但导航拥挤、缺少响应式、页面多为纵向卡片列表，尚未形成成熟的学习工作台。

本轮升级的完成目标：

- 用户打开应用后能明确知道“继续什么、复习什么、为什么推荐”。
- 聊天中的术语可以无中断地展开、分支、进入笔记、练习和复习。
- 所有掌握度变化都有可追溯的练习、面试或复习证据。
- 桌面端具备高效的多区域工作流，移动端不依赖缩小桌面布局。
- 动效用于表达上下文、层级和状态变化，不使用无意义的装饰动画。
- 每阶段都有固定视口和关键状态截图，并经过人工视觉复核。

## 2. 范围与非目标

### 2.1 本计划包含

- 全局应用壳、导航、响应式布局和交互基础组件。
- 聊天、消息级分支、术语上下文侧栏和会话状态管理。
- “今日学习”行动页，但保留现有 `/` 聊天路由，先新增 `/today`，不立即迁移首页。
- 笔记、资源、SQL 实践、面试、复习、白板、分析的交互升级。
- `Concept / Skill / Attempt / ReviewLog / LearningEvent` 等支撑跨模块闭环的最小数据改造。
- Playwright 截图脚本、核心流程 E2E、桌面与移动端视觉验收。

### 2.2 本计划暂不包含

- 微服务、消息队列、完整 xAPI/LRS 实现。
- 多用户、云端同步、协作编辑。
- 通用无限画布或分支自动合并。
- 一开始就引入向量数据库或深度 Knowledge Tracing 模型。
- 同时支持多种编程语言沙盒；先把 SQL 学习闭环做完整。

## 3. 产品与视觉方向

### 3.1 产品定位

界面定位为**安静、清晰、可持续使用的个人学习工作台**。它不是营销首页，也不是由大量统计卡片拼成的后台。复杂能力通过上下文侧栏、快捷操作和渐进展开呈现，主任务区始终只保留一个明确焦点。

### 3.2 标志性交互

本项目保留并强化一个标志性设计：**会话卡片分支 + 学习上下文轨道**。

- 从具体消息或术语创建分支时，当前卡片轻微后退，新分支从锚点位置进入主舞台。
- 右侧上下文轨道同步显示当前术语、来源、掌握证据和可执行动作。
- 用户跨到笔记、练习、面试或复习时，上下文轨道保持同一个 `Concept`，减少“切页面后失忆”。
- 移动端不保留三栏，而是把上下文轨道变成底部抽屉。

### 3.3 色彩令牌

现有紫色品牌保留，但降低大面积使用，避免整个产品只剩单一紫色。

| 名称 | 建议值 | 用途 |
|------|--------|------|
| Canvas | `#F6F7F9` | 页面背景 |
| Paper | `#FFFFFF` | 主工作面与弹层 |
| Ink | `#1B1D22` | 主要文字 |
| Violet | `#6558D9` | 品牌、主操作、当前路径 |
| Teal | `#087F76` | 掌握、成功、知识关联 |
| Amber | `#B96D0B` | 到期、提示、学习中 |
| Coral | `#C44E63` | 错误、重学、风险 |

深色主题采用同一语义映射，不另造一套品牌色。黄色只用于填充或状态背景，不作为小字号文字色。

### 3.4 字体与信息密度

- 中文正文优先系统 CJK 字体栈，拉丁字母沿用 Geist Sans。
- 代码、事件 ID、时间和数据使用 Geist Mono。
- 页面标题控制在 20–24px，面板标题 14–16px，数据标签 11–12px。
- 不使用营销式超大标题；信息工具以内聚、可扫描为主。
- 字距固定为 `0`，不使用负字距和按视口缩放字号。

### 3.6 动效规则

| 场景 | 时长 | 表达目的 |
|------|------|----------|
| 按钮、标签状态 | 120–160ms | 即时反馈 |
| 侧栏、抽屉、会话切换 | 180–220ms | 空间关系 |
| 会话分支进入主舞台 | 240–300ms | 血缘与上下文继承 |
| 掌握度变化 | 300ms 内 | 让证据到状态的变化可见 |
| 页面进入 | 不做统一入场动画 | 避免重复干扰 |

所有动画只改变 `transform`、`opacity` 或必要的局部尺寸；支持 `prefers-reduced-motion`，关闭后仍保持完整语义。

### 3.7 实施优先级（2026-08-14 调整）

- 桌面端是主要使用场景，复杂交互、信息密度和视觉精修以 `1440x900` 为核心验收视口。
- `1024x768` 只保证工作流和信息层级完整，不为平板单独扩展复杂手势。
- 移动端不作为本轮重点，只保证无关键内容丢失、无不可恢复遮挡且核心操作可完成。
- 阶段 0、2、17、18 保留四视口检查；其余阶段默认只做桌面截图，涉及导航、抽屉或明显溢出风险时再补窄屏截图。

## 4. 目标信息架构

| 一级区域 | 页面 | 核心任务 |
|----------|------|----------|
| 今日 | `/today` | 继续上次学习、处理到期复习、完成一个薄弱点练习 |
| 学习 | `/`、`/notes`、`/resources`、`/practice` | 学、记、读、练 |
| 测验 | `/interview`、`/review` | 主动检索、面试检验 |
| 洞察 | `/analytics`、`/whiteboard` | 解释进步、发现薄弱点、决定下一步 |

桌面端左侧导航呈现一级区域；同一区域的页面放在二级菜单或顶部局部标签中。移动端底栏只呈现四个一级区域，二级页面通过区域首页或抽屉进入。

## 5. 目标领域对象

| 对象 | 最小职责 |
|------|----------|
| `Concept` | 术语规范名、别名、定义、来源和关联技能 |
| `Skill` | 能力节点、前置依赖、目标权重 |
| `ConceptMention` | 术语在哪条消息、笔记或资源中出现 |
| `AssessmentItem` | 练习或面试题、技能标签、难度、评分规则 |
| `Attempt` | 用户答案、结果、提示次数、耗时、反馈 |
| `ReviewCard` | 复习卡正反面、来源、所属概念 |
| `ReviewLog` | 每次复习前后参数和算法版本 |
| `MemoryItem` | 目标、偏好、薄弱点、成功解释方式及来源 |
| `LearningEvent` | 标准化动作、对象、结果、上下文、版本和幂等键 |
| `MasteryProjection` | 从 Attempt、ReviewLog 和事件投影出的当前掌握状态 |

业务表继续保存当前状态；事件负责审计与趋势，不在当前阶段追求纯 Event Sourcing。

## 7. 每阶段截图审查流程

每个涉及 UI 的阶段严格执行以下循环：

1. 使用固定种子数据或 Playwright 网络 mock 构造稳定状态。
2. 启动 Windows 兼容开发服务器。
3. 以 `1440x900` 截取关键状态；密集布局补 `1024x768`，移动端只在最终回归检查基础可用性。
4. 使用图像查看工具逐张检查，不以 DOM 正常或构建通过代替视觉检查。
5. 记录问题：布局、层级、密度、对比度、溢出、状态表达、操作可发现性。
6. 修复后生成 `after` 截图，不覆盖问题截图。
7. 同一阶段截图通过后再更新阶段状态。

截图命名：

```text
<phase>-<route>-<state>-<viewport>-before.png
<phase>-<route>-<state>-<viewport>-after.png
```

例如：

```text
06-chat-branch-open-desktop-after.png
10-review-answer-mobile-after.png
11-practice-sql-error-tablet-after.png
```

## 8. 质量门禁

### 8.1 功能门禁

- [ ] 所有 API 输入经过运行时校验。
- [ ] 所有写操作具备错误反馈；关键写操作具备幂等或事务保障。
- [ ] 分支继承正确上下文，流式请求不串会话。
- [ ] 所有掌握状态都有 Attempt 或 ReviewLog 证据。
- [ ] 跨模块深链接刷新后仍能恢复。

### 8.2 UI 门禁

- [ ] 桌面与 1024 宽度无重叠和无意义横向滚动，移动端通过最终基础可用性门禁。
- [ ] 主操作在首屏可发现，每个区域不超过一个视觉主按钮。
- [ ] 桌面复杂能力通过多区域呈现，移动端不丢失关键内容与恢复路径。
- [ ] 所有 loading、empty、error、success 状态有明确界面。
- [ ] 图标按钮有 tooltip/aria-label，键盘焦点可见。
- [ ] reduced motion 下交互完整。

### 8.3 数据与学习有效性门禁

- [ ] 事件具备 object、result、context 和 schemaVersion。
- [ ] 复习保存完整 ReviewLog，调度器可替换、可复算。
- [ ] 面试和实践写入结构化 Attempt。
- [ ] 分析指标能回溯到证据，不把点击数或消息数包装成掌握度。
- [ ] AI 生成的定义、笔记、评分和建议均能显示来源或解释依据。

## 9. 风险与对策

| 风险 | 影响 | 对策 |
|------|------|------|
| 一次改完整个产品 | 回归面过大、难以判断设计优劣 | 严格按 0–18 阶段推进，每阶段截图和测试后再继续 |
| 前端先行但数据对象不统一 | 形成更多一次性 UI | 阶段 4 和阶段 7 先建立事件与 Concept 主干 |
| 动效过多 | 干扰长时间学习 | 只为层级、因果和状态变化动效，统一时长并支持 reduced motion |
| 移动端照搬桌面 | 信息拥挤、控件不可用 | 移动端使用底栏、抽屉和单列流程，独立截图验收 |
| AI 截图状态不稳定 | 无法比较前后差异 | 使用固定种子数据或请求 mock，不依赖实时模型输出 |
| 真实数据迁移风险 | 用户学习记录损坏 | 迁移前备份、事务迁移、临时数据库测试、外键检查 |
| “本地”认知与在线推理不一致 | 用户误解数据边界 | 设置页明确本地存储与 DeepSeek 传输边界，后续提供本地模型适配器 |

## 10. 执行确认点

这是 Deep Mode 计划，方向已确认并于 2026-08-14 开始执行：

- 使用“左侧导航 + 主工作区 + 上下文轨道”，替换当前拥挤的全顶部导航。
- 保留 `/` 作为聊天，新增 `/today`；等用户实际体验后再决定是否把 `/today` 设为启动页。
- 保留 card-stack 作为会话血缘的标志性交互，不把所有模块都做成卡片堆。
- 接受为截图/E2E 引入 Playwright，为图标引入 lucide，为无障碍弹层按需引入少量 Radix/shadcn primitives。
- 按阶段执行并在每个 UI 阶段展示截图审查结果，而不是一次性完成后才反馈。
- 后续前端设计以桌面端为主，移动端仅保留基础可用性门禁，不做逐阶段精修。
