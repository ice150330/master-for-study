# 使用回路优化方向（下一轮迭代候选清单）

> 日期：2026-08-24
> 来源：多工作区落地后的全回路使用复盘（对照产品设计蓝图与 08-14 升级计划，基于提交 `9cbc425` 的实现现状）
> 性质：方向清单与优先级判断，供下一轮实施计划挑选与排序；本文不承诺全部实施

## 0. 总判断

主干回路（今日 → 对话 → Concept → 检验 → 复习 → 分析/白板）已贯通，但有 **4 个点动摇产品核心承诺**，另有回路断点一批与实用性短板一批。核心张力：**记忆层的数据只喂给了给人看的 UI，没有喂给 AI 老师；复习队列的信噪比没有治理；多工作区与单源卡片原则出现冲突**。

---

## A. 动摇核心承诺（P0/P1.5）

### A1 · AI 老师跨会话失忆 —— 蓝图第一承诺未兑现 【P0】

- **现象**：新开会话问老师，它不知道用户上周学过什么、哪里薄弱、面试错在哪。
- **根因**：`/api/chat` 系统提示词 = 术语标注指令 + 风格 + 深浅 + 本轮资源；对话上下文只有当前会话树前缀。`termMasteries` / `learningEvents` / 面试错题史从未注入提示词。
- **方向**：构造「学习者画像摘要」注入系统提示词——当前工作区掌握度薄弱的 N 个概念 + 最近学习主题摘要 + （可选）面试错题关联概念。控制 token 预算（fastModel 下每次数百 token 级），设置面板可开关。
- **验收要点**：新会话中老师能主动延续此前话题（"你上次对 MVCC 的理解还差 X"）；不注入时行为不变。

### A2 · 术语自动入队 = 复习队列灌水 + 标注无纠错 【P0】

- **现象**：一次长对话产出十几个 `[[术语]]` 全部进复习队列；标注错误/过度标注无处理入口。
- **根因**：`upsertTerm` 自动 `ensureMastery` 入队，无筛选；两段式标注纯靠模型自觉（初期计划的"种子词典过滤 + 白名单"未做）。
- **方向**（三件事组合）：
  1. **入队前置确认**：新概念首次出现在 Concept 轨道时标记"待确认"，加入复习需用户一键确认（或批量）；
  2. **标注纠错**：Term 触发器提供"标错了/不需要高亮"动作，维护本地白名单/黑名单并在解析时过滤；
  3. **队列治理**：复习页支持跳过/降频/移出队列（区分"不熟"与"不需要"）。
- **验收要点**：一轮 20 消息对话后，默认进队的新卡 ≤ 用户确认数；黑名单词不再高亮。

### A3 · 多工作区破坏单源卡片 —— 产品决策项 【P1.5 · 待拍板】

- **现象**：同一概念在两个工作区 = 两行 terms、两份掌握度、两张复习卡。
- **根因**：`terms` / `termMasteries` 均为 workspace 维度；多工作区落地后"同一张卡被引用而非复制"只在区内成立。
- **两个方向二选一**（决策后再排实施）：
  - **方向甲 · 概念全局化**：`terms` 提升为全局表，新增「工作区接触记录」（提及/复习/面试按区记），掌握度全局一份。符合"单源卡片"原意，迁移成本高（跨区同名合并策略要定义）。
  - **方向乙 · 学科宇宙**：明确"工作区 = 独立学科宇宙，概念不跨区"，同名概念各区独立。改文档即可，但"缓存学两遍"的体验保留。
- **倾向**：方向甲，但依赖 A2 的确认机制先降低脏数据量，否则合并迁移会被历史噪音卡死。

### A4 · 间隔重复只在"用户主动回来"时有效 【P0】

- **现象**：无任何提醒机制；周末型用户回来面对逾期卡堆，体验是负罪感而非引导。
- **方向**：Web Notification API（页面打开时申请权限，到期/逾期 N 张时提醒）+ favicon/标题到期数徽标 + 逾期引导文案（"先清最旧的 5 张"）。
- **验收要点**：应用关闭时不开系统级提醒（本地 Web 的边界，写入设计文档）；打开时徽标与提醒准确。

## B. 回路断点（P1/P2）

| # | 断点 | 现象 / 根因 | 方向 | 优先级 |
|---|------|------------|------|--------|
| B1 | 导出无导入 | 备份闭环只有一半；换机器无法恢复 | 带 schema 校验的事务式 import（先迁移校验再整库替换/合并），入口放设置面板，导入前强制再导出一份当前库 | P1 |
| B2 | 概念定义不可编辑 | LLM 一次性写入，错误扩散到复习卡/知识图/轨道 | Concept 轨道增加"修正定义"（写 note 版本式留痕），修正后复习卡同步 | P1 |
| B3 | 成长目标只是徽标 | `growthGoal` 不驱动任何东西；知识图是通用树 | 多岗位能力树种子（蓝图 §8）；按目标高亮主线/推荐下一步 | P2 |
| B4 | 隐性感知未实现 | `durationMs` 录了不用，FSRS 只吃四档评级 | 起步：把复习耗时/面试反应时纳入薄弱度权重（非 FSRS 参数），供今日推荐与面试选题 | P2 |
| B5 | 复习卡形态单一 | 只有名词→定义 | 笔记块生成问答卡；概念间关系卡（"MVCC 和锁的区别"）；保持 FSRS 调度不变，扩展卡片来源 | P2 |
| B6 | 场景绑定列未接线 | `interviewStyle` / `reviewStyle` 建列未用 | 面试映射（严师→rigorous 等）+ 复习完成语措辞；或删列保持诚实 | P2 |

## C. 实用性短板（P2/P3）

1. **全局内容搜索**：顶栏只搜页面名；补 FTS5 或 SQLite LIKE 起步——"我上次在哪聊过 WAL"跨会话/笔记/资源检索。【P2】
2. **冷启动**：新用户资源库空、无引导。最低配：首个工作区引导对话 + 资源种子若干。【P2】
3. **成本与异常感知**：token 用量展示（按会话/日）；DeepSeek 限流/欠费给出可区分的错误文案。【P2】
4. **工作区删除/归档**：只有增改切；补归档 + 删除（含数据 cascade 或导出后删）。【P2】
5. **学习时长统计**：对话阅读时间不入度量；补"会话停留近似"或滚动深度，标注为近似值。【P3】
6. **工作区切换体验**：整页 reload 丢输入；改为路由级状态保活或切换前暂存输入框。【P3】
7. **移动端**：维持既有"基础护栏"决策，不投入（记录在案，非目标）。【非目标】

## 建议执行顺序

1. **P0 批**：A2（队列治理，先做——它同时是 A3 迁移的前置）→ A1（记忆注入）→ A4（到期提醒）
2. **P1 批**：B1（导入）→ B2（定义可编辑）→ C1（全局搜索）
3. **决策点**：A3 概念归属（甲/乙），决策后单独排期
4. **P2 批**：B3/B4/B5/B6 + C2/C3/C4，按需挑选
5. **非目标**：C7 移动端精修、多用户/云同步、本地模型适配器（维持后置）
