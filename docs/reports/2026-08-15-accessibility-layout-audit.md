# 阶段 17：可访问性与布局质量审查报告

日期：2026-08-15
范围：键盘路径、焦点管理、语义、目标尺寸、深浅主题、减少动态、桌面布局稳定性与窄屏底线

## 1. 结论

本阶段把全局交互质量从“组件大多可点”收敛为可重复验证的系统门禁。主验收视口是 1440×900、1024×768 与 1600×900；390×844 只验证今日、对话、复习三条基础路径可导航且无页面级横向溢出，不为手机端重做桌面工作台。

关键工作区已通过严重级与致命级 axe 自动扫描，键盘可跳到主内容；会话选择器、Concept 轨道支持 Escape，并在弹层关闭后恢复焦点。普通非内联按钮目标统一守住 24×24 CSS 像素，长链接不会撑破笔记正文，减少动态模式关闭非必要过渡，高对比度模式保留系统焦点轮廓。

这不是完整的 WCAG 合规声明。自动扫描只能覆盖可机器判断的部分，真实读屏、放大软件、语音控制与用户测试仍属于发布前专项验证。

## 2. 成熟规范参考

| 官方资料 | 设计要求 | 本项目落地 |
|---|---|---|
| [W3C Focus Visible](https://www.w3.org/WAI/WCAG22/Understanding/focus-visible) | 键盘可操作界面必须让用户看见当前焦点 | 全局 `:focus-visible` 使用 3px 主色环和背景分隔；加入“跳到主要内容”，弹层建立首焦点、Escape 与焦点返回 |
| [W3C Reflow](https://www.w3.org/TR/WCAG22/#reflow) | 内容在窄视口或放大后不应丢失信息或强迫双向滚动，二维工具可按用途例外处理 | 1024–1600 检查页面级横向溢出；笔记长文本强制断行；白板保持固定桌面画布，画布内部负责缩放和平移 |
| [W3C Target Size (Minimum)](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum) | 一般指针目标至少可容纳 24×24 CSS 像素，正文内联目标可例外 | 自动枚举所有可见按钮，排除正文内联目标后逐个检查；术语、关闭、复制与资源动作补齐尺寸 |
| [MDN prefers-reduced-motion](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/At-rules/%40media/prefers-reduced-motion) | 根据系统设置减少或替换非必要动态 | `reduce` 下关闭动画和过渡，实践主操作实测过渡时长为 0；主题切换期间暂时禁用颜色过渡，避免中间帧低对比 |

## 3. 交互修正

- 全局壳增加跳转主内容链接，主滚动区成为可编程聚焦目标。
- 会话选择器改用模态 Popover，搜索框为首焦点，提供弹层内关闭按钮，点击关闭或 Escape 后返回触发器。
- Concept 详情轨道支持 Escape；聊天轨道增加明确的补充区域名称。
- 加载骨架使用 `status` 语义；面试、分析、白板的视觉分组补充可访问名称。
- 术语、资源删除高亮、代码复制等紧凑控件补足目标面积；长消息、长 URL 与资源详情可安全断行。
- 深浅主题调整主色与危险色对比；Windows 强制颜色模式下由系统色绘制选择、当前项和焦点。

## 4. 布局与运行时修正

- 笔记列表、正文与目录在紧凑桌面按可用宽度收敛，1600 宽屏保持主从阅读密度。
- 白板在 1024 仍保持稳定的画布与 19rem 节点轨道双栏，避免 React Flow 首帧获得零高度；不为手机端引入另一套画布结构。
- 消息滚动区增加布局与绘制隔离，动态内容不会推动外层工作台。
- 为历史 ReviewCard 增加 FSRS 读取兼容层：旧版 `new/learning` 数据会先规范化到当前库允许的稳定性、难度和计数范围，再由下一次正常复习持久化合法结果。由此修复真实 `/today` 因旧卡片参数越界返回 500 的问题。

## 5. 自动门禁

新增 `tests/e2e/accessibility-layout.spec.ts`，覆盖：

- 10 个关键路由的 WCAG 2 A/AA、2.2 AA 标签 axe 扫描；严重级与致命级问题必须为 0。
- 可见非内联按钮的 24×24 CSS 像素目标尺寸检查。
- 1024、1440、1600 三档桌面宽度的页面级横向溢出与 CLS < 0.1 检查。
- 深色主题、强制颜色、减少动态、长文本和 390 基础路径。
- 跳到主内容、会话 Popover、Concept 轨道的真实键盘流程。

阶段验证结果：Vitest 15 个文件、80 条测试通过；ESLint 与 TypeScript 通过；本阶段专属 Playwright 为 4 通过、4 按项目视口跳过。受影响模块回归覆盖聊天、UI 基础、壳导航、Concept、笔记、复习、今日和白板，发现的两个旧定位兼容点均修正并复测通过。

## 7. 残余边界

- axe 无严重问题不等于读屏体验已完整验收；后续发布前仍需 NVDA + Chromium 人工走一次核心闭环。
- 白板、代码编辑器与宽数据表是具有二维意义的桌面工具，窄屏只保证页面壳不失控，不承诺完整手机操作效率。
- 本阶段未引入数据库迁移；FSRS 兼容层是读取时修正，旧数据会在用户下一次复习时自然写回当前格式。
