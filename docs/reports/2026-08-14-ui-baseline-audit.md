# Mentor UI 视觉基线审查

> 日期：2026-08-14
>
> 阶段：学习闭环升级阶段 0
>
> 采集目录：`data/ui-captures/00-baseline/`

## 采集结果

- 页面：聊天、复习、实践、成长分析、白板。
- 视口：`1440x900`、`1024x768`、`390x844`、`360x800`。
- 产物：20 张 PNG 截图、4 份布局审计 JSON。
- 运行结果：4 个 Playwright 项目全部通过，5 个页面均返回成功且无控制台错误。
- 图片尺寸：所有 PNG 均严格匹配目标视口；截图和审计数据位于已忽略的 `data/`，不进入 Git。

## 基线结论

| 页面 | 桌面端主要问题 | 窄屏基础问题 | 后续主要方向 |
|------|----------------|--------------|--------------|
| 聊天 | 单张会话卡几乎占满工作面，消息分散在两端，中部有大量无效空白；分支卡悬浮在模式控制附近，血缘关系不清晰 | 文档宽度达到 `626px`；顶部导航和右侧工具被截断，术语分支卡与模式控件争抢空间 | 收敛消息阅读宽度，建立左导航、主舞台和上下文轨道；让分支从消息锚点进入 |
| 复习 | 单卡流程可读，但“今日 20 张”没有进度、预计耗时和下一间隔；首屏以下大面积空白 | 文档宽度达到 `542px`，主要由顶部导航造成；卡片本身尚可使用 | 强化主动回忆、队列进度、间隔反馈和撤销，不增加装饰卡片 |
| 实践 | 更像 SQL 输入框而非学习任务；示例查询、编辑器、运行按钮和结果说明缺少明确的任务顺序 | 文档宽度达到 `626px`；主表单能缩放，但顶部导航被截断 | 重组为题目、Schema、编辑器、结果四区，补任务反馈与证据回写 |
| 分析 | 六张掌握度卡和三张面试卡权重接近，紫色高亮只表达数值而非洞察；最近活动只有事件名和时间 | 文档宽度达到 `446px`；统计卡可排成三列，但导航仍越界 | 以“负荷、薄弱点、真实进步、下一步”替代累计卡片墙，并提供证据入口 |
| 白板 | 两块大容器占据大量空间；技能树整体缩小，节点不可操作、不可筛选，首屏只看到图的一部分 | 文档宽度达到 `446px`；技能树虽整体可见，但节点文字已经不可读 | 默认展示当前概念的一到两跳局部图，增加缩放、平移、筛选和节点详情 |

## 跨页面问题

1. 顶部导航把八个模块与两个工具长期同权展示。桌面端缺少“今日、学习、测验、洞察”的任务层级；窄屏则直接产生 `446–626px` 的文档宽度。
2. 页面标题与主要内容集中在中间窄列，但缺少稳定的侧栏、上下文和操作区，导致桌面空间看似宽裕却没有形成工作台效率。
3. 多数模块只有默认和空白状态，缺少加载、错误、成功、重试和请求中的视觉规范。
4. 紫色同时承担品牌、当前导航、主按钮和重点统计，青色只零散用于成功动作，语义层级不足。
5. 白板、分析和聊天都有“内容存在但不可行动”的问题：数据或节点没有明确解释、来源和下一步入口。

## 实施优先级

本轮后续设计以桌面端为主：`1440x900` 负责复杂交互和视觉完成度，`1024x768` 负责基本工作流适配。移动端仅作为基础可用性门禁，在全局导航、最终精修和最终验收阶段检查关键内容不丢失，不再逐阶段做精细视觉优化。

阶段 1 先收敛颜色、层级、焦点和状态组件；阶段 2 再处理造成所有窄屏横向溢出的全局导航，并建立桌面学习工作台结构。
