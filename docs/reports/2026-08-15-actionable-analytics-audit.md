# 阶段 15：可行动成长分析审查报告

日期：2026-08-15
范围：成长分析数据投影、7/30 天趋势、薄弱技能、进步与证据流水、桌面视觉验收

## 1. 设计结论

旧页面只展示累计术语数、面试正确率和事件类型，无法回答“今天先做什么”和“这个判断来自哪条证据”。本阶段把页面改为学习控制台：首屏只保留一个推荐动作，趋势与比率严格来自不可变记录，薄弱项和活动行都能回到 Concept、Attempt 或 ReviewLog。

界面唯一强化的视觉元素是“学习节律轨”：每日柱体同时表达学习、评测和复习，红色圆点单独表达提示次数；其他部分使用分隔线、紧凑指标和表格，避免把分析页做成装饰性卡片墙。

## 2. 成熟产品设计参考

| 官方资料 | 可复用形式 | 本项目落地 |
|---|---|---|
| [Anki Statistics](https://docs.ankiweb.net/stats.html) | 区分今日负荷、长期趋势和未来到期；提示单日正确率噪声较大 | 今日负荷与 7/30 天趋势分离；不足 3 次不计算评测、复习和提示百分比 |
| [Khan Academy Mastery Progress](https://support.khanacademy.org/hc/en-us/articles/360031123551-How-can-I-monitor-mastery-progress-) | 汇总数字可继续下钻到单个技能报告 | 薄弱技能名称、图表日期和活动行都可下钻到具体学习对象 |
| [Duolingo Practice Tab](https://blog.duolingo.com/guide-to-duolingo-practice-hub/) | 把历史错误直接转为针对性练习 | 失败、提示和面试降级证据会提高 Concept 优先级，并给出“针对练习”入口 |

## 3. 数据口径

| 区域 | 真相源 | 规则 |
|---|---|---|
| 学习活动 | `LearningEvent` | 对话、概念、笔记、资料行为；排除布局与管理事件 |
| 评测通过 | `PracticeAttempt` + `InterviewAttempt` | 练习成功或面试正确；样本少于 3 次不输出百分比 |
| 复习保留 | `ReviewLog.rating` | `hard/good/easy` 计为成功取回，`again` 计为失败 |
| 提示依赖 | `PracticeAttempt.hintCount` | 使用过至少一次提示的练习占比 |
| 薄弱技能 | 掌握状态 + Attempt + ReviewLog | 重学、到期、失败、提示、降级和 Again 加权排序；不生成不可解释的综合掌握分 |
| 最近进步 | 成功 Attempt / ReviewLog | 只展示任务通过、面试进阶或成功取回等可验证结果 |

## 4. 交互与状态

- `7 天 / 30 天` 切换经 `/api/analytics` 运行时校验并重新投影。
- 每根日柱都是按钮；点击后证据流水只显示该日，重复点击恢复全部日期。
- 流水支持学习、评测、复习三类筛选，行点击进入相关对象。
- 空工作区不生成趋势；小样本明确显示“仅 N 次样本，至少需要 3 次”。
- 1440 使用趋势 + 20rem 薄弱项轨道；1024 自动改为上下布局，不特别为移动端扩展复杂交互。

## 5. 截图审查

截图目录：`data/ui-captures/15-actionable-analytics/`

- `overview-*`：首屏推荐、今日负荷、7 天节律和薄弱技能。
- `30-days-*`：30 天范围；无活动日期保留为空白，不做插值。
- `day-drilldown-*`：日期选中后展示指标来源、真实进步和当日对象流水。
- `assessment-filter-*`：当日评测证据筛选。
- `small-sample-*`：少量活动存在，但三个比率均拒绝输出趋势判断。
- `new-workspace-*`：零负荷、零事件与可执行起步动作。

视觉复盘：1440 首屏能同时看到动作、负荷、趋势和前三个薄弱项；1024 的顶部负荷区保持 2×2，趋势柱无裁切，薄弱项移到图表下方。日期下钻表格在两个桌面宽度均未出现横向滚动或文字覆盖。

## 6. 验证结果

- 投影单测覆盖行为分类、日期补齐、提示累计、小样本阈值、比率计算与薄弱项排序。
- Route Handler 合同覆盖非法 14 天范围与合法 7 天响应。
- Playwright 覆盖六个固定视觉状态，并对真实本机数据库 `/analytics` 做渲染烟测。
- 本阶段不改数据库结构，不需要迁移。
