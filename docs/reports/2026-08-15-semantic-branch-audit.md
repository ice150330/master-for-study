# 阶段 6：消息级语义分支验收

## 功能结果

- `sessions` 新增 `rootSessionId` 与 `forkedFromMessageId`，分支血缘同时落入会话行和 `session_created` 事件上下文。
- 前端创建分支只提交消息锚点；服务端由锚点反推父会话，拒绝不存在或跨会话锚点。
- `/api/chat` 不再信任客户端拼装的完整历史，只接收本次新消息；服务端沿祖先链读取共享前缀，并在每一层截断到子分支锚点。
- 术语动作会立即创建分支并自动发送结合原上下文的首问，不再停留在空白子会话。
- 每条已完成消息在悬停或键盘聚焦时提供“从这里分支”图标动作。
- 会话切换使用 280ms 位移、缩放和饱和度过渡；祖先竖条与分支扇继续表达父子关系。
- 1024 宽度隐藏竖条堆与分支扇，改用顶部面包屑和子分支选择器；按本轮要求不扩展手机专项设计。

## 截图审查

截图位于 `data/ui-captures/06-semantic-branch/`，不进入 Git。

- `before`：根会话、锚点术语和既有兄弟分支关系明确。
- `motion-mid`：新分支进入时保留父会话竖条，卡片以轻微右移、淡入和去饱和中间态表达层级变化。
- `after`：术语分支已包含自动首问与回答，标题下方显示直接父会话。
- `sibling`：返回父会话后可切到兄弟分支，原根会话消息未变化。
- `compact-path`：1024 × 768 下使用水平路径，标题、消息和输入区无重叠或裁切。

## 自动验证

- Vitest：8 个文件、43 个用例通过。
- 数据库集成覆盖：根会话字段、合法锚点、跨会话锚点拒绝、分叉点后消息不进入子会话上下文。
- Playwright：1440 分支全流程和 1024 紧凑路径均通过；验证请求体不再携带客户端历史数组。
- TypeScript、ESLint、Next.js production build 均作为阶段提交前质量门执行。
